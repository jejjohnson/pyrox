    Likelihoods API¶

    The pyrox.likelihoods module holds the protocols that every observation model and variational guide in the pyrox packages subclasses, so a package built on the core can take a pyrox likelihood without depending on pyrox-gp. It carries no numerics: expectations and per-site derivatives of a likelihood are computed by gaussx in the packages that need them. pyrox_gp re-exports the protocols, so pyrox_gp.Likelihood is pyrox.likelihoods.Likelihood.

    Protocols¶

    Likelihood ¶

    Bases: Module

    Abstract base for observation models.

    Implements the conditional p(y | f), summed over points. The advanced inference strategies in pyrox-gp integrate log p(y | f) against a Gaussian cavity via any gaussx.AbstractIntegrator. Concrete scalar-latent likelihoods (GaussianLikelihood here; BernoulliLikelihood, PoissonLikelihood, StudentTLikelihood in pyrox-gp) and multi-latent ones (SoftmaxLikelihood, HeteroscedasticGaussianLikelihood) subclass it.

    Multi-latent likelihoods declare latent_dim: int as a static field (e.g. latent_dim = num_classes for softmax). Scalar likelihoods may omit the field; consumers should read getattr(lik, "latent_dim", 1).

    Examples:

    A Laplace observation model with unit scale:

    >>> import jax.numpy as jnp
>>> from pyrox.likelihoods import Likelihood
>>> class LaplaceLikelihood(Likelihood):
...     def log_prob(self, f, y, X=None):
...         return jnp.sum(-jnp.abs(y - f) - jnp.log(2.0))
>>> float(LaplaceLikelihood().log_prob(jnp.zeros(2), jnp.zeros(2)))
-1.386...

    inference strategies in pyrox-gp integrate ``log p(y | f)`` against a
    Gaussian cavity via any `gaussx.AbstractIntegrator`. Concrete

        with a conditional warp). Scalar observation models ignore it.

    Guide ¶

    Bases: Module

    Abstract base for variational posterior families.

    Concrete guides (DeltaGuide, MeanFieldGuide, LowRankGuide, FullRankGuide, etc.) live in pyrox-gp. The whitening principle keeps optimization geometry well-conditioned — sample from a unit-scale latent and unwhiten with the prior Cholesky.

    Two distinct entry points:

    • sample / log_prob — pure variational draws and densities. sample(self, key) returns a draw from q(f); log_prob(self, f) evaluates log q(f). Neither touches the NumPyro trace.
    • register(name, prior) (optional) — the NumPyro-integration hook invoked by pyrox_gp.gp_sample when a guide is supplied. Use it to register a sample / param site (or compose one out of guide state) under name and return the latent function value. Concrete guides that participate in gp_sample should implement this; the protocol leaves it unspecified so guides usable purely outside NumPyro stay valid.

    Examples:

    A point-mass guide at a fixed vector:

    >>> import jax.numpy as jnp
>>> from pyrox.likelihoods import Guide
>>> class PointGuide(Guide):
...     loc: jnp.ndarray
...     def sample(self, key):
...         return self.loc
...     def log_prob(self, f):
...         return jnp.asarray(0.0)
>>> PointGuide(jnp.zeros(3)).sample(None).shape
(3,)

    Observation models¶

    AbstractObservation is the base of an observation model that declares its own hyperparameters and builds a gaussx likelihood holding the data; latent_dim (1 by default) is the number of latents per site. pyrox_lgm re-exports it, so pyrox_lgm.AbstractObservation is pyrox.likelihoods.AbstractObservation.

    pyrox-gp's likelihoods are observation models too: each one's build(y, theta, data) returns the gaussx likelihood below, with the inputs in data["X"], and log_prob(f, y, X) evaluates it. pyrox_gp.GaussianLikelihood subclasses pyrox.likelihoods.GaussianLikelihood, so the closed-form paths that dispatch on the core class take it.

    pyrox name gaussx likelihood it builds
    pyrox_gp.GaussianLikelihood gaussx.GaussianLikelihood
    pyrox_gp.BernoulliLikelihood gaussx.BernoulliLikelihood
    pyrox_gp.PoissonLikelihood gaussx.PoissonLikelihood
    pyrox_gp.StudentTLikelihood gaussx.StudentTLikelihood
    pyrox_gp.SoftmaxLikelihood gaussx.SoftmaxLikelihood
    pyrox_gp.HeteroscedasticGaussianLikelihood gaussx.HeteroscedasticGaussianLikelihood

    AbstractObservation ¶

    Bases: Module

    Observation model \(p(y \mid \eta, \theta)\) with its own hyperparameters.

    An observation model declares its hyperparameters \(\theta\) (theta_spec) and builds, for data y at a given \(\theta\), the gaussx likelihood that inference runs on (build). Per-site data other than y (offsets, trial counts, inputs) passes through data. The per-site methods (site_distribution, site_log_prob, site_cdf) evaluate \(p(y_i \mid \eta_i, \theta)\) directly, for diagnostics. pyrox-lgm's observation models (pyrox_lgm.Gaussian, pyrox_lgm.Poisson, …) subclass it, and pyrox_lgm.AbstractObservation is this class.

    The linear predictor eta has shape (N,) when latent_dim is 1 (the default) and (N, latent_dim) otherwise: one row of latents per site, as for a softmax over \(K\) classes (latent_dim = K) or a heteroscedastic Gaussian (latent_dim = 2). A subclass changes it by overriding the property, or with a static field that has a default (latent_dim: int = eqx.field(static=True, default=2)).

    The class registers no NumPyro sites, and the core imports no gaussx: build is annotated Any, and a subclass returns a gaussx.AbstractLikelihood. The one exception is the core's own DistLikelihood, whose build returns the two arguments of gaussx.CallableLikelihood for the gaussx-backed packages to wrap.

    Attributes:

    Name Type Description
    name AbstractVar[str]

    Prefix of the hyperparameter names, which join \(\theta\) as f"{name}.{key}" (pyrox-lgm uses "lik").

    Examples:

    A heteroscedastic Gaussian with two latents per site, the mean and the noise scale before a softplus (gaussx's likelihood takes the two latent columns concatenated, eta.T.reshape(-1)):

    >>> import equinox as eqx
>>> import jax
>>> import jax.numpy as jnp
>>> import numpyro.distributions as dist
>>> from pyrox.likelihoods import AbstractObservation
>>> class Heteroscedastic(AbstractObservation):
...     name: str = eqx.field(static=True, default="lik")
...     @property
...     def latent_dim(self):
...         return 2
...     def build(self, y, theta, data):
...         import gaussx as gx
...         return gx.HeteroscedasticGaussianLikelihood(y)
...     def site_distribution(self, eta, theta, data):
...         return dist.Normal(eta[:, 0], jax.nn.softplus(eta[:, 1]))
>>> obs = Heteroscedastic()
>>> eta = jnp.zeros((3, obs.latent_dim))
>>> obs.site_log_prob(jnp.zeros(3), eta, {}, {}).shape
(3,)

    class AbstractObservation(eqx.Module):
    r"""Observation model $p(y \mid \eta, \theta)$ with its own hyperparameters.

    An observation model declares its hyperparameters $\theta$ (`theta_spec`)
    and builds, for data ``y`` at a given $\theta$, the gaussx likelihood
    that inference runs on (`build`). Per-site data other than ``y``
    (offsets, trial counts, inputs) passes through ``data``. The per-site
    methods (`site_distribution`, `site_log_prob`, `site_cdf`) evaluate
    $p(y_i \mid \eta_i, \theta)$ directly, for diagnostics. pyrox-lgm's
    observation models (`pyrox_lgm.Gaussian`, `pyrox_lgm.Poisson`, …)
    subclass it, and `pyrox_lgm.AbstractObservation` is this class.

    The linear predictor ``eta`` has shape ``(N,)`` when `latent_dim` is 1
    (the default) and ``(N, latent_dim)`` otherwise: one row of latents per
    site, as for a softmax over $K$ classes (``latent_dim = K``) or a
    heteroscedastic Gaussian (``latent_dim = 2``). A subclass changes it by
    overriding the property, or with a static field that has a default
    (``latent_dim: int = eqx.field(static=True, default=2)``).

    The class registers no NumPyro sites, and the core imports no gaussx:
    `build` is annotated ``Any``, and a subclass returns a
    `gaussx.AbstractLikelihood`. The one exception is the core's own
    `DistLikelihood`, whose `build` returns the two arguments of
    `gaussx.CallableLikelihood` for the gaussx-backed packages to wrap.

    Attributes:
        name: Prefix of the hyperparameter names, which join $\theta$ as
            ``f"{name}.{key}"`` (pyrox-lgm uses ``"lik"``).

    Examples:
        A heteroscedastic Gaussian with two latents per site, the mean and
        the noise scale before a softplus (gaussx's likelihood takes the two
        latent columns concatenated, ``eta.T.reshape(-1)``):

        >>> import equinox as eqx
        >>> import jax
        >>> import jax.numpy as jnp
        >>> import numpyro.distributions as dist
        >>> from pyrox.likelihoods import AbstractObservation
        >>> class Heteroscedastic(AbstractObservation):
        ...     name: str = eqx.field(static=True, default="lik")
        ...     @property
        ...     def latent_dim(self):
        ...         return 2
        ...     def build(self, y, theta, data):
        ...         import gaussx as gx
        ...         return gx.HeteroscedasticGaussianLikelihood(y)
        ...     def site_distribution(self, eta, theta, data):
        ...         return dist.Normal(eta[:, 0], jax.nn.softplus(eta[:, 1]))
        >>> obs = Heteroscedastic()
        >>> eta = jnp.zeros((3, obs.latent_dim))
        >>> obs.site_log_prob(jnp.zeros(3), eta, {}, {}).shape
        (3,)
    """

    name: eqx.AbstractVar[str]

    @property
    def latent_dim(self) -> int:
        """Latents per site: the trailing size of ``eta``; 1 by default."""
        return 1

    def theta_spec(self) -> dict[str, tuple[nd.Distribution, Transform]]:
        """Hyperparameters of the likelihood; none by default.

        Returns:
            ``{key: (prior, transform)}``, where ``transform`` maps the
            unconstrained value to the prior's support.
        """
        return {}

    @abstractmethod
    def build(
        self, y: Array, theta: dict[str, Array], data: Mapping[str, ArrayLike]
    ) -> Any:
        """The gaussx likelihood holding ``y`` at hyperparameters ``theta``.

        Args:
            y: Observations, ``(N,)``.
            theta: Hyperparameters, keyed as in `theta_spec`.
            data: Per-site data other than ``y`` (offsets, trial counts,
                inputs).

        Returns:
            A `gaussx.AbstractLikelihood` over the ``N`` sites (annotated
            ``Any``, because the core imports no gaussx); for
            `DistLikelihood`, the ``(log_density, data)`` pair that
            `gaussx.CallableLikelihood` takes.
        """

    def site_distribution(
        self,
        eta: Float[Array, " N"] | Float[Array, "N L"],
        theta: dict[str, Array],
        data: Mapping[str, ArrayLike],
    ) -> nd.Distribution:
        """``p(y_i | eta_i)`` per site as a NumPyro distribution (batched in eta).

        ``eta`` is ``(N,)`` for one latent per site and ``(N, latent_dim)``
        otherwise. Diagnostics may evaluate it on quadrature nodes, so for
        one latent ``eta`` may carry trailing axes after the sites'
        (broadcast per-site data against them). Only diagnostics need it
        (`pyrox_lgm.diagnostics`), so an observation model that does not
        define it still fits.

        Raises:
            NotImplementedError: Unless a subclass defines it.
        """
        raise NotImplementedError(
            f"{type(self).__name__} defines no site_distribution, which the "
            "diagnostics need"
        )

    def site_log_prob(
        self,
        y: Array,
        eta: Float[Array, " N"] | Float[Array, "N L"],
        theta: dict[str, Array],
        data: Mapping[str, ArrayLike],
    ) -> Array:
        """``log p(y_i | eta_i)`` per site, from `site_distribution`."""
        return jnp.asarray(self.site_distribution(eta, theta, data).log_prob(y))

    def site_cdf(
        self,
        y: Array,
        eta: Float[Array, " N"] | Float[Array, "N L"],
        theta: dict[str, Array],
        data: Mapping[str, ArrayLike],
    ) -> Array:
        """``P(Y_i <= y_i | eta_i)`` per site, from `site_distribution`."""
        return jnp.asarray(self.site_distribution(eta, theta, data).cdf(y))

    Bring your own likelihood¶

    DistLikelihood turns a NumPyro distribution into an observation model, for a likelihood gaussx has no class for (a zero-inflated Poisson, a Beta, a censored Gaussian). Pass make_dist(eta_i, theta, data_i), which returns site \(i\)'s distribution of \(y_i\), and the hyperparameters it reads as theta:

    import jax.numpy as jnp
import numpyro.distributions as dist
from pyrox.likelihoods import DistLikelihood

zip_lik = DistLikelihood(
    lambda eta, th, d: dist.ZeroInflatedPoisson(gate=th["pi"], rate=jnp.exp(eta)),
    theta={"pi": 0.2},
)

    Its log density is the distribution's log_prob, site by site. The core imports no gaussx, so build(y, theta, data) does not return a gaussx likelihood as the other observation models do: it returns the per-site log density and data that gaussx.CallableLikelihood takes. pyrox-gp's inference (Laplace, Gauss-Newton, posterior linearisation, EP, the SVGP expected log likelihood, CVI) and pyrox-ssm's Markov strategies wrap that pair as gaussx.CallableLikelihood(*zip_lik.build(y, {}, data)), so they take its site derivatives and expectations from gaussx. The inputs reach make_dist as data_i["X"].

    theta holds arrays that are leaves of the module, so they receive gradients and can be NumPyro sample values: inside a model, DistLikelihood(make_dist, theta={"pi": numpyro.sample("pi", dist.Beta(2.0, 4.0))}) passed to pyrox_ssm.markov_laplace_factor puts the gate under NUTS. make_dist itself is a static field, so a parameter it closes over never trains. make_dist must return one site's distribution for one site's inputs, and log_prob(f, y, X) calls it on every site at once, so it should broadcast over a leading site axis as NumPyro distributions do.

    pyrox_gp.DistLikelihood is this class. The old one-argument link, DistLikelihood(lambda f: dist.Bernoulli(logits=f)), still works and ignores theta and the inputs; DistLikelihood(dist_fn=...) warns and points to make_dist.

    DistLikelihood ¶

    Bases: AbstractObservation, Likelihood

    Observation model over any NumPyro distribution, \(p(y_i \mid \eta_i, \theta)\).

    The user's make_dist(eta_i, theta, data_i) returns site \(i\)'s distribution, and its log_prob is the per-site log density

    \[ \ell(\eta_i, d_i) = \log p(y_i \mid \eta_i, \theta, \mathrm{data}_i), \qquad \log p(y \mid \eta) = \sum_i \ell(\eta_i, d_i), \]

    so a likelihood gaussx has no class for (zero-inflated Poisson, Beta, a censored Gaussian) gets Laplace, EP and the Markov strategies.

    The core imports no gaussx, so build does not return a gaussx likelihood, unlike other observation models: it returns the pair (log_density, data) that gaussx.CallableLikelihood takes, where log_density(eta_i, d_i) is \(\ell\) and data is {"y": y, "data": data}, every leaf with a leading site axis of length \(N\). pyrox-gp's inference and pyrox-ssm's strategies recognise a DistLikelihood and wrap the pair as gaussx.CallableLikelihood(*lik.build(y, theta, data)), which gives the per-site derivatives and expectations. log_prob(f, y, X) and the per-site diagnostics (site_distribution) call make_dist on every site at once, so make_dist must broadcast over a leading site axis, as NumPyro distributions do; index inputs from the end (data_i["X"][..., 0]).

    The hyperparameters \(\theta\) that make_dist reads are the theta field, updated key by key by the theta passed to build (pyrox-gp and pyrox-ssm pass none). They are array leaves of the module, so they receive gradients and may be NumPyro sample values. pyrox-gp and pyrox-ssm pass the inputs as data_i = {"X": x_i}. pyrox_lgm.inla does not take a DistLikelihood yet: it uses what build returns as a gaussx likelihood. The class registers no NumPyro sites.

    The old one-argument link DistLikelihood(lambda f: dist.Bernoulli(logits=f)) still works: a callable with exactly one required positional argument is wrapped to ignore theta and data_i, keeping the defaults of any optional ones (lambda f, df=3.0: ...), so a make_dist must take theta and data_i without defaults. DistLikelihood(dist_fn=...) warns and always does the same.

    The callable cannot carry trainable parameters

    make_dist is a static field, so anything it closes over is invisible to eqx.filter_grad and silently never trains. Put scalar hyperparameters in theta; for a parameterized link (a warp, a network), write a Likelihood subclass holding it as a child module.

    class DistLikelihood(AbstractObservation, Likelihood):
    r"""Observation model over any NumPyro distribution, $p(y_i \mid \eta_i, \theta)$.

    The user's ``make_dist(eta_i, theta, data_i)`` returns site $i$'s
    distribution, and its ``log_prob`` is the per-site log density

    $$
    \ell(\eta_i, d_i) = \log p(y_i \mid \eta_i, \theta, \mathrm{data}_i),
    \qquad
    \log p(y \mid \eta) = \sum_i \ell(\eta_i, d_i),
    $$

    so a likelihood gaussx has no class for (zero-inflated Poisson, Beta, a
    censored Gaussian) gets Laplace, EP and the Markov strategies.

    The core imports no gaussx, so `build` does not return a gaussx
    likelihood, unlike other observation models: it returns the pair
    ``(log_density, data)`` that `gaussx.CallableLikelihood` takes, where
    ``log_density(eta_i, d_i)`` is $\ell$ and ``data`` is
    ``{"y": y, "data": data}``, every leaf with a leading site axis of
    length $N$. pyrox-gp's inference and pyrox-ssm's strategies recognise a
    `DistLikelihood` and wrap the pair as
    ``gaussx.CallableLikelihood(*lik.build(y, theta, data))``, which gives
    the per-site derivatives and expectations. ``log_prob(f, y, X)`` and the
    per-site diagnostics (`site_distribution`) call ``make_dist`` on every
    site at once, so ``make_dist`` must broadcast over a leading site axis,
    as NumPyro distributions do; index inputs from the end
    (``data_i["X"][..., 0]``).

    The hyperparameters $\theta$ that ``make_dist`` reads are the ``theta``
    field, updated key by key by the ``theta`` passed to `build` (pyrox-gp
    and pyrox-ssm pass none). They are array leaves of the module, so they
    receive gradients and may be NumPyro sample values. pyrox-gp and
    pyrox-ssm pass the inputs as ``data_i = {"X": x_i}``. `pyrox_lgm.inla`
    does not take a `DistLikelihood` yet: it uses what `build` returns as a
    gaussx likelihood. The class registers no NumPyro sites.

    The old one-argument link ``DistLikelihood(lambda f: dist.Bernoulli(logits=f))``
    still works: a callable with exactly one required positional argument is
    wrapped to ignore ``theta`` and ``data_i``, keeping the defaults of any
    optional ones (``lambda f, df=3.0: ...``), so a ``make_dist`` must take
    ``theta`` and ``data_i`` without defaults. ``DistLikelihood(dist_fn=...)``
    warns and always does the same.

    !!! warning "The callable cannot carry trainable parameters"
        ``make_dist`` is a **static** field, so anything it closes over is
        invisible to ``eqx.filter_grad`` and silently never trains. Put
        scalar hyperparameters in ``theta``; for a parameterized link (a
        warp, a network), write a `Likelihood` subclass holding it as a
        child module.

    Attributes:
        make_dist: ``(eta_i, theta, data_i) -> numpyro.distributions.Distribution``,
            site $i$'s distribution of $y_i$.
        theta: Hyperparameter values ``make_dist`` reads, as arrays.
        name: Prefix of the hyperparameter names (``"dist"``).

    Examples:

        gaussx-backed package wraps it into:

    def __init__(
        self,
        make_dist: Callable[..., nd.Distribution] | None = None,
        theta: Mapping[str, ArrayLike] | None = None,
        *,
        name: str = "dist",
        dist_fn: Callable[[Array], nd.Distribution] | None = None,

        if dist_fn is not None:
            if make_dist is not None:
                msg = "pass make_dist or the deprecated dist_fn, not both"
                raise TypeError(msg)
            warnings.warn(
                "DistLikelihood(dist_fn=...) is deprecated; pass the callable "
                "as make_dist: DistLikelihood(make_dist=...) or positionally.",
                DeprecationWarning,

                # equinox's metaclass calls __init__; point at the caller
                skip_file_prefixes=(str(Path(eqx.__file__).parent),),
            )

            make_dist = _LatentOnly(dist_fn)

            msg = "DistLikelihood needs make_dist(eta_i, theta, data_i)"
            raise TypeError(msg)

            make_dist = _LatentOnly(make_dist)

    def dist_fn(self) -> Callable[[Array], nd.Distribution]:
        """Deprecated: the one-argument link ``f -> Distribution``; use ``make_dist``.

        The old one-argument callable when one was passed, else ``make_dist``

    def _theta(self, theta: Mapping[str, Array]) -> dict[str, Array]:
        """The ``theta`` field, updated by the caller's ``theta``."""
        return {**self.theta, **theta}

    def build(
        self, y: Array, theta: dict[str, Array], data: Mapping[str, ArrayLike]
    ) -> tuple[Callable[[Float[Array, ""], PyTree], Float[Array, ""]], PyTree]:
        r"""The per-site log density and data that `gaussx.CallableLikelihood` takes.

        Args:
            y: Observations, ``(N,)``.
            theta: Hyperparameters, overriding the ``theta`` field key by key.
            data: Per-site data other than ``y``, every leaf with a leading
                site axis of length ``N``.

        Returns:
            ``(log_density, site_data)``: ``log_density(eta_i, d_i)`` is
            $\log p(y_i \mid \eta_i, \theta, \mathrm{data}_i)$ for a scalar
            ``eta_i`` and one site's slice ``d_i`` of
            ``site_data = {"y": y, "data": data}``.

        site_data = {
            "y": jnp.asarray(y),
            "data": {key: jnp.asarray(value) for key, value in data.items()},
        }
        return log_density, site_data

    def site_distribution(
        self,
        eta: Float[Array, " N"],
        theta: dict[str, Array],
        data: Mapping[str, ArrayLike],
    ) -> nd.Distribution:

    def likelihood_accepts_inputs(lik: Likelihood) -> bool:
    """Whether ``lik.log_prob`` takes the optional trailing ``X``.

    The protocol widened in gh-204 to carry the inputs an
    input-dependent observation model conditions on. Third-party
    `Likelihood` subclasses written against the original
    ``log_prob(self, f, y)`` are still concrete and valid, and handing
    one a third positional argument raises ``TypeError`` at the first
    quadrature evaluation -- so probe rather than assume.

    Static Python on the unbound signature, evaluated once per trace, so
    it costs nothing under ``jit``.

    Args:
        lik: The likelihood to probe.

    Returns:
        ``True`` if ``lik.log_prob`` takes a third positional argument.

    Examples:
        >>> from pyrox.likelihoods import GaussianLikelihood, likelihood_accepts_inputs
        >>> likelihood_accepts_inputs(GaussianLikelihood(noise_var=1.0))
        True
    """
    try:
        params = list(inspect.signature(lik.log_prob).parameters.values())
    except (TypeError, ValueError):  # unintrospectable callable
        return False
    if any(p.kind is inspect.Parameter.VAR_POSITIONAL for p in params):
        return True
    positional = [
        p
        for p in params
        if p.kind
        in (
            inspect.Parameter.POSITIONAL_ONLY,
            inspect.Parameter.POSITIONAL_OR_KEYWORD,
        )
    ]
    return len(positional) >= 3
